## File structure — `/opt/cykruit-v2/`

```
/opt/cykruit-v2/
├── deploy.sh            # core deploy logic, one target at a time
├── deploy-menu.sh        # interactive wrapper (prompts for target 1-6 + tag)
├── build-env.sh          # pulls SSM Parameter Store + Secrets Manager -> .env files
├── docker-compose.yml    # all 14 services (hand-maintained, NOT the git-tracked root one)
├── .env.prod             # generated backend env (do not hand-edit, regenerated by build-env.sh)
└── .env.prod.admin       # generated admin-app env (same)
```

## Deploy

```bash
# Interactive (recommended)
sudo /opt/cykruit-v2/deploy-menu.sh
# prompts: target (1=cykruit-app, 2=admin-app, 3=cykruit-ui, 4=admin-ui, 5=migrate, 6=All), tag

# Direct, single target
sudo /opt/cykruit-v2/deploy.sh prod <target> <tag>
# targets: migrate | cykruit-app | admin-app | cykruit-ui | admin-ui
# tag: short git sha (e.g. 4e38edd) or "latest"
```

`deploy.sh` auto-runs `docker system prune -af` and ECR login every time — no
separate cleanup step needed.

## Regenerate env files (after any SSM Parameter/Secret change)

```bash
sudo /opt/cykruit-v2/build-env.sh prod
# writes .env.prod (from /cykruit-v2/prod/backend/*) and .env.prod.admin (from /cykruit-v2/prod/admin-backend/*)
```

## Restart a single container without a full deploy

```bash
sudo bash -c '
export ENV=prod
export REDIS_PASSWORD=$(grep "^REDIS_PASSWORD=" /opt/cykruit-v2/.env.prod | cut -d"=" -f2-)
cd /opt/cykruit-v2 && docker compose up -d --force-recreate <service-name>
'
```

`ENV`/`REDIS_PASSWORD` are Compose-interpolation vars, not container env — must
be exported in-shell; `--env-file` does not set them.

## Validate compose YAML before restarting anything

```bash
cd /opt/cykruit-v2 && sudo ENV=prod REDIS_PASSWORD=x docker compose config --quiet && echo VALID
```

## SSM Parameter Store / Secrets Manager (region `ap-south-1`)

- Params (recursive fetch): `/cykruit-v2/prod/backend/*` -> `.env.prod`,
  `/cykruit-v2/prod/admin-backend/*` -> `.env.prod.admin`
- Secrets: `/cykruit-v2/prod/backend/{db-password,jwt-secret,redis-password,resend-api-key,google-oauth,razorpay,aws-s3-credentials,ai-vendor-keys,bedrock-credentials(optional)}`,
  `/cykruit-v2/prod/admin-backend/{jwt-secret,resend-api-key}`
- Adding a new one? Just add the Parameter/Secret, then re-run
  `build-env.sh prod` — no script change needed unless it's a computed/assembled
  value (like `DATABASE_URL`, which is assembled from `db-host`/`db-port`/`db-password`).
- `DATABASE_URL`, `REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD`, `EMAIL_FROM` are
  shared infra values copied from `$BACKEND_OUT` into `$ADMIN_OUT` at the end of
  `build-env.sh` (same RDS `cykruit` DB, same self-hosted `redis` container) —
  don't duplicate them as separate `admin-backend/` params.

## Gotchas hit this session (don't repeat)

- `docker-compose.yml` `environment:` keys must be indented **2 spaces deeper**
  than `environment:` itself — a same-level key silently makes `environment`
  parse as `null`, not a mapping, and fails compose validation
  (`services.X.environment must be a mapping`) only when compose actually runs,
  not on save.
- `deploy.sh`'s `admin-app`/`admin-ui` targets used the ECR **image repo name**
  (`cykruit-admin-app`/`cykruit-admin-ui`) instead of the compose **service
  name** (`admin-app`/`admin-ui`) — fixed, but check for this class of mismatch
  if a new target is ever added.
- Next.js `output: "standalone"` resolves `next.config.ts`'s `rewrites()`
  destinations at `next build` time (baked into `.next/routes-manifest.json`).
  Container-runtime env vars (`docker-compose.yml` `environment:`) **cannot**
  override them — these must be passed as Docker build-args in CI instead.
